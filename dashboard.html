專案儀表板 · 更新於 8/19 · 資料來自工作紀錄 · 目前用的版本:6 個功能全部上線,加「同時開好幾張單子」的前五塊,已換裝你的電腦;第六塊做完了但還沒換裝
現在在哪:「一次同時開好幾張單子」這包功能六小塊全部做完、全部驗收完。最後一塊「接進日常流程」剛結案 — 以後你問「接下來做什麼」的時候,只要有好幾張單子彼此不卡,它會自己推薦走快車道;切單子那關也會在整批都沒標先後順序時停下來問你一句。但這一塊還沒裝到你的電腦上,所以現在打「接下來做什麼」還是舊的回答。
這次做了什麼(尚未換裝):三件事。一、問「接下來做什麼」時會自己推薦快車道 — 同一包工作裡有兩張以上彼此不卡的單子時,它會推「一次開好幾張」,並把「一張一張慢慢來」列成另一個選擇;判斷誰卡誰不是用眼睛看,是直接呼叫快車道自己那支算名單的程式,不另外寫一套會各說各話的版本。二、切單子那關會提醒漏標 — 整批單子一個先後順序都沒標的時候,發出去之前先問你一句「這批彼此都沒有先後關係,對嗎?」。因為「真的沒有」跟「忘了標」在單子上長得一模一樣,而快車道完全照這份標記排班 — 忘了標的那批會被當成全部能同時開,兩張改到同一處的單子就會並排跑起來,撞在最後收回主線那關,那時候已經來不及問你了。切單子這關是最後一個問得到你的地方。三、自動檢查守住上面那一問 — 有人把那句話刪掉,檢查當場變紅並指名是哪一份說明書。反悔的話:這三件都是改說明書和檢查程式,拿掉就是刪幾段的事。
下一步:先決定要不要現在把新版裝到你電腦上 — 想裝就說一聲,一個指令的事(裝回舊版也是一個指令)。不裝的話功能都做好了,只是你這台機器上還用不到。
之後想繼續推進,問一句/next(另一種助理:$next)就會告訴你該開哪一棒。另外八張小單子都是你判「之後再修」的,沒有急件。

  • 新抓到這次新加的那道自動檢查,只擋得住「把那句話刪掉」,擋不住「把那句話的意思反過來寫、但關鍵字留著」。也就是有人把切單子那份說明改成「都沒標先後順序就直接發出去,不用問你」,自動檢查照樣全綠 —而那道檢查存在的唯一理由,就是守住「先問你一句」這件事。把專案裡所有同一種寫法的檢查數過一遍:這種寫法一共兩道,兩道都有同一個洞(另一道是守「貼連結前要先上傳」的那道)。另外一道用不同寫法的當對照,它兩種改法都擋得住,所以不是驗的方法有問題。等你決定要不要修。
  • 已結案整批跑完會做一次「臨時工作區有沒有清乾淨」的檢查,但它把整台電腦上所有工作區都算進來,包含助理自己長期用的那幾份 — 所以永遠報「沒清乾淨」,反過來真的有殘留時也看不出來。已經修好、當場演給你看、你點頭收掉,而且這次真的跑批次時它第一次就答對。
  • 已結案說明書裡「把總結貼到單子上」有三個地方,只有貼給你看的那則沒寫成可以整行複製的指令。已經補齊三處一致;順手還抓掉一段本來要寫進去、但實測是錯的說明。
  • 帶著走貼總結的那行指令裡,單子編號要在兩個地方各寫一次 — 改一個忘另一個,總結會安靜地貼到別張單子上,不會報錯。你決定之後再修(要動程式的輸出格式,不適合順手做)。
  • 已結案助理列「現在可以同時開哪幾張單子」那份名單,在你的黑底終端機上三段標題(要開 / 排隊 / 還卡著)是一堆亂碼,讀不出來哪張屬於哪段;單子標題裡只要有 emoji 或箭頭,指令還會當場中斷。已經修好、演給你看、你點頭收掉,新版已換裝,而且自動檢查會守住:以後誰把「印名單」搬回說明書裡的臨時指令、或漏了設定文字編碼,檢查當場變紅。
  • 帶著走上面那份名單的說明書,只寫了一種終端機的貼法;你如果用 Windows 內建的那兩種終端機,照抄會貼不動。你決定之後再修。
  • 帶著走守著「文字編碼有沒有設好」的那道檢查,有一個合法的例外寫法認得太寬鬆 — 只要在註解裡提到那個字,檢查就會放行。現在沒有人這樣繞過,但以後有可能無聲繞過。你決定之後再修。
  • 已解決那兩句對不上實況的驗收標準,你已經點頭改成正確版本,原始的需求文件也同步改好了 — 下次重驗會照新的標準跑,不會再拿舊句子對。沒有程式要改。
  • 已修好有三份說明檔案,裝到別台電腦之後會叫你去看一個沒被一起裝過去的檔案 — 照著讀就是「找不到檔案」。已經修掉,而且順手讓自動檢查以後會自己抓到同一種問題:把當初那句話種回去,檢查當場就變紅並指出是哪一份檔案。
  • 帶著走你問「接下來做什麼」時,如果那件工作上沒有留下現成的交接說明,助理會改照一張對照表回答 — 那張表還沒有電腦自動把關,少寫一種寫法不會被擋下來。你先前決定這條之後再修。
  • 已結案自我檢查跑完的時候,中間會先印一行看起來像出錯的字 — 那其實是它自己故意造的假案例。現在那行前面會標明「這是假的」,不會再嚇你一跳。這條已經演給你看、你點頭收掉了,而且順手讓檢查自己守住這個標示:有人哪天把「這是假的」拿掉,檢查當場就會變紅。
  • 帶著走「檢查有沒有做錯 → 自動開一張修正單」這條路,在另一種助理上還沒真的被觸發過一次(那一輪剛好全部通過,沒東西可開)。你決定之後再補跑一次驗證。
  • 已結案每件工作結尾那行交接說明會附一個連結,指向這次改了什麼 — 但東西還沒上傳到網路上之前,你點下去會是「找不到頁面」。已經修好:現在一定先上傳才貼連結,而且自動檢查會守住這個順序,有人刪掉或搬動上傳那步就當場變紅。順手發現另外兩個地方(結案、系統自我檢討)有同一個問題,一起補了。
  • 帶著走上面那道「有沒有先上傳」的檢查,遇到一種還沒設定過上傳目標的工作分支時,會直接報一句看不太懂的錯誤訊息,而不是好好地說「還有東西沒上傳」。它不會放行、只是話講得醜,你決定之後再修。
  • 帶著走「檢查」這道環節的說明書寫死了一種只有第一種助理才有的看網頁工具;第二種助理用的是另一套。這輪跑的工作單不碰網頁所以沒撞到,等到有畫面的功能才會遇到。你決定之後再修。

最近幫你做的決定

  • 8/19「兩張改到同一處」那段判斷,以前只有自動檢查在核對「說明書裡那幾句話還在不在」,從來沒有人真的把它跑過一次 — 現在改成每次檢查都當場開一個拋棄式的專案、真的撞一次、看它答不答得對。之所以要這樣,是因為這一段前後被抓到四次答錯,而每一次出錯的當下檢查都是綠的。你這邊看到的差別:以後有人把這段改壞,檢查會當場變紅,而不是等到真的撞車了才在你面前報錯票號。
  • 8/19上面那個檢查跑的是說明書裡的原文,不是另外抄一份到測試裡 — 抄一份的話,說明書改了、測試還在跑舊的那份,就會出現「檢查全綠但實際是壞的」這種最難查的情況。代價是測試要多做一步把那段字抽出來,幾行的事。
  • 8/19這個檢查放在專案自己的檢查程式裡,不放進會裝到你電腦上的那份 — 它要臨時開一個專案副本才跑得起來,裝到你機器上只會讓東西變重;而且它掛在原本就有的那個指令底下,你要跑檢查還是同一行,不用多記。
  • 8/19那份名單裡「還卡著」那一段,不只寫哪張卡著,還一併寫出「卡在誰後面」 — 因為那正是你要判斷的資訊,讓助理自己心算等於把一半判斷搬到沒人檢查得到的地方。你這邊看到的差別:名單直接讀得出來誰在等誰。
  • 8/19看不到狀態的那種卡關對象,一律當成「還卡著」,不猜「應該做完了」 — 猜錯的後果正好是這個功能要防的事(兩張會互相打架的單子被同時開)。代價是偶爾會保守地多留一張在等待區,你當場說一聲就能推翻。
  • 8/19那些對你講的話(「只有一張就用單張指令就好」「這幾張要一起推嗎?」)也交給自動檢查守著,不只守程式算得對不對 — 你是照著那兩句話點頭的,改壞了會無聲無息地漂掉,下一次你看到的就不是你驗過的東西。
  • 8/19亂碼的修法不是在說明書那行指令前面加設定,而是把「印名單」這件事搬進程式裡、在程式裡把文字編碼釘死 — 因為留在說明書裡的指令是測不到的地方,測不到就會再壞一次。你這邊看到的差別:貼的指令變短了,而且不用先調任何設定。
  • 8/19順手把整個專案裡所有「會自己印東西給你看」的程式都一起釘死編碼,並立成規矩交給自動檢查守著 — 雖然只有一支是你真的踩到的。好處是下一支忘了釘的程式當場變紅;代價是這次多動了三個檔案各一行。
  • 8/19新增一道檢查,守的是「說明書叫你貼的那行指令,有沒有還走進程式裡」— 因為這個亂碼從頭到尾都不是程式算錯,而是說明書叫你貼的那行繞過了程式。只認「有沒有繞過」,不比對整段文字長相,所以你改排版、換句話說都不會誤報。
  • 8/17「貼連結前要先上傳」這條新檢查寫成通用規矩(任何地方要貼這種連結都得先上傳),不只釘住剛修好的那一處 — 所以順手把另外兩個同款缺口(結案、系統自我檢討)也補了,雖然本來不在這張單子的範圍裡。好處是以後新寫的環節忘了上傳也會被當場擋下;代價是這次多動了兩個檔案各一行。想拿掉就是刪一小段的事。
  • 8/17那道檢查認的是「真的會去上傳的那行指令」,不認說明開頭那句「上傳後再寫回工作單」的摘要 — 因為只認摘要的話,有人把真正上傳那步刪掉,檢查還是綠的,等於白守。
  • 8/17要確認「那行假案例真的有標明是假的」,用的方法是讓自我檢查再跑一次自己、去讀螢幕上真正印出來的字,而不是在程式裡面自己問自己 — 因為要守的就是你眼睛看到的那幾行。好處是有人把標示拿掉會當場被抓到;代價是檢查跑兩遍,慢個幾秒。想拿掉的話刪一小段就好。
  • 8/17「交接那行指到的功能到底存不存在」這條新檢查,放在「整份專案一起檢查」的時候跑,不放進「單一功能自己檢查」裡 — 因為要看得到全部功能才答得出來。你這邊看到的東西沒有差別,照樣一個指令跑完;想搬回去也只是搬幾行。
  • 8/17安裝指令接受「要多帶幾個字」才會裝到全電腦到處能用,不自己寫一套安裝程式 — 你要記的那行長一點,其他不變,說明書早就寫的是這行。當初把落點寫錯的原因也記下來了:只讀了人家的說明書、沒有真的打一次就寫進需求文件。以後這種「會過時的外部事實」要先實跑再寫。
  • 8/17那三份會叫人去看不存在檔案的說明,修法是讓自動檢查自己認得「這句在講你自己的專案、不是我帶著走的檔案」,而不是去改文件的措辭來閃過檢查 — 文件原文一個字沒動,以後寫類似說明也不用為了過檢查遷就用字。想改回來很容易,規則就一小段。
  • 8/17自動檢查的範圍從「只看每個功能的主檔案」擴到「每一個會跟著裝過去的說明檔」 — 之前這個洞是隱形的,連續兩次驗收都沒抓到,因為驗收用的就是這支有盲區的檢查。
  • 8/17公開時附上一份大方的使用授權書 — 沒有這份,別人在法律上連拿去用都不行。代價是你放棄限制別人怎麼用它;想收回來,已經拿走的人不受影響。
  • 8/17過去每一次修改都會記下作者信箱,你的信箱因此跟著公開了 — 決定不動它。要清掉得把整份歷史重寫,會連帶弄壞現有紀錄的對照編號;而且同一個信箱在你另一個早就公開的專案上大概率已經看得到,清了也沒差。
  • 8/17那份「怎麼驗證這套做法有沒有比較好」的計畫書照原樣公開 — 裡面只有你自己的檢討,沒有別人的資料,對照的也是你自己早就公開的專案。
  • 8/17說明書裡不寫沒實際查證過的指令 — 原本想順手多寫一個「只裝在這個專案」的用法,查不到根據就整句刪掉。寧可少寫,也不要你照著打卻打不通。
  • 8/17「交接那行字要寫兩種寫法」這條規矩,直接抄在每個功能檔裡,不另外抽一份共用的 — 抽共用的反而會讓要跟著同步的副本變更多;真正守門的是自動檢查,已經有了。
  • 8/17新加的自動檢查塞進原本那支檢查程式裡,不另外開一套 — 你只要記一個指令就能跑完全部;之後真要換成正式的測試工具,搬過去是小工程。
  • 8/17只檢查「指名到某個檔案」的設定,不檢查「只寫到資料夾」的那種 — 少了一種很少見的漏網情況,換來不會亂報一堆假警報。
  • 8/17有一個功能專門在整理這份專案本身,替它開了例外通道 — 目前用不到,但先留著,哪天用到不用再改。
  • 8/17安裝用現成的公用工具,不自己寫一套 — 省下自己維護的力氣,代價是照人家的規矩走。

  • 已結案「交接連結點下去是壞的」 — 修好後演給你看,你三條都點頭,新版已換裝,規矩也交給電腦守了。
  • 已結案「名單在終端機上是亂碼」 — 修好後四種情況逐條演給你看,你全部點頭,新版已換裝,規矩也交給電腦守了。
