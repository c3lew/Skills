## #96 拍板結果

`stream_encoding_issues` 只認正規寫法：

```python
if __name__ == "__main__":
```

`"__main__" == __name__`、`__name__ in ("__main__",)`、先存成變數再判斷，以及 `if/else`
反寫不列入目前規則。這是有限語法約定的邊界，不代表尚有排定實作。

## 為什麼保留

#96 把判準從「推論程式會不會跑到某行」換成「pin 是否位於正規 `__main__` block 第一層」，
藉此移除 557 行不收斂的可達性分析。窮舉等價入口寫法會重新打開開放式判準，因此 client
選擇保留正規寫法這一條明確天花板。

## 已有對照

#97 的 self-check 固化三格：正規寫法缺 pin 判紅；反著寫與 `in (...)` 不被辨識。這三格是
刻意邊界的回歸紀錄。

## 後續

除非 client 重新拍板擴大正規入口語法，否則本票只作邊界紀錄，不進 build 排程。
