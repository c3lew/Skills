平行開工:三張票同時做,做完一張張合回主線

這一片要做的事:你點頭之後,三張互不相干的票各自拿一份獨立的專案副本開工,各自做完各自驗過,再一張一張合回主線,合完整批再驗一次,最後回報「3 張已合併」。

先講清楚:哪些是真的跑過的

QA 這一輪把底下每一塊零件都實跑驗過了 — 三個工作區真的互相看不到對方的檔、三張真的一張一張合回主線、合完的主線上整批驗證全綠、中文和 emoji 沒有壞碼、貼回票上的那條路真的貼上 GitHub。

QA 唯一補不上的是最上面那一層 — 你點頭之後,每個工作區裡真的去做那張票。那一層在這次 demo 當場補跑了:拿 #61 + #62 兩張真的票真的跑了一輪 /build-batch,詳見下面「真跑一輪」那段。三條驗收項現在都有實跑證據。

「工作區真的互相看不到對方」怎麼驗的

QA 在一份拋棄式的專案副本上真的開了三個工作區,各自改各自的檔案、各自送出。第三個工作區裡去撈「所有人的檔案」,只撈得到自己那一個 — 另外兩個的檔案根本不存在。

「跑這個指令就會得到那個工作區」這條因果,QA 那輪還沒連起來(印字串跟開工作區是分開跑的)— 這次 demo 當場補跑一輪把它連上了,見上面「真跑一輪」。

QA 在拋棄式副本上真的把三張一張一張合回主線 — 不是同時。三次合併的紀錄首尾相接,對得上帳;每合完一張,那張的工作區當場收掉(三份 → 兩份 → 一份 → 沒了),不會三份一路佔著硬碟。

合完之後在主線上又把整套檢查跑了一次,全綠 — 這關就是在吃「各自都對、合起來壞」的風險。

票是什麼建議
#61 整批收尾時會做一次「清乾淨了沒」的檢查,但這台機器上永遠報「沒清乾淨」— 因為 Claude Code 自己有幾份常駐的工作副本住在同一個專案裡,被誤算進去了。 已修 — 判準改成只問 .git/batch-worktrees/ 底下有沒有東西,再加一行確認 branch 還留著。六種現場都實測過,而且剛剛在真的批次上跑,答對。
#62 操作手冊裡三處同型的指令,兩處寫得可以直接複製貼上,最後一處要 agent 自己拼。 已修 — 補成一行可以整段複製的指令。過程中還抓掉一段本來要寫進文件、但實測是錯的說明。
#63 貼批次總結的指令裡,票號要在兩個地方各寫一次。改一個忘另一個,總結會安靜地貼到別張票上,而且不會報錯。 之後修 — 票已開。要動程式的輸出介面,不適合塞進這一輪;而且真的貼錯票你翻票時看得出來,不是無聲的資料損壞。
